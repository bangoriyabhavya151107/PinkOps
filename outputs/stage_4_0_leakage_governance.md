## 1. Executive Summary & Purpose

In sports predictive modeling, data leakage is the most prevalent cause of false model efficacy. When future information (events occurring after a ball is bowled, current match totals, or downstream match results) infiltrates pre-delivery features, models achieve deceptively high validation scores but collapse in live deployment.

This document establishes the **Causal Timeline Governance Specification** for Operation Pink Panther. It formally audits every variable utilized across the Seven-Layer Reliability Architecture, articulates the strict pre-delivery timeline rule ($t^-$), categorizes potential leakage pathways, and enforces calibrated, scientifically defensible leakage statements.

## 2. The Fundamental Causal Timeline Rule ($t^-$)

Every feature $\mathbf{X}(t^-)$ supplied to the expectation and pressure models must satisfy the strict causal precedence constraint:

$$\text{FeatureTimestamp} \le t^- < \text{delivery\_bowled}(t) < \text{delivery\_outcome}(t) \le \text{match\_end}$$

```
   MATCH CHRONOLOGY ──────────────────────────────────────────────────────────►
   
   Past History             Pre-Match State        Pre-Delivery (t^-)       Delivery (t)       Post-Delivery / Match End
   [t < Match Start]        [t = 0]                [Immediately Before Run-up] [Ball Bowled]   [t > Delivery]
   ─────────────────        ───────────────        ────────────────────────── ─────────────   ─────────────────────────
   • Venue Historical Rate  • Team Pre-Match Elo   • Balls Remaining Before   • Runs Scored    • Final Match Score
   • Competition Baseline   • Toss Opted           • Runs Required Before     • Wicket Taken   • Winning Team ID
   • Historical Player H2H  • Home / Away Status   • Current Batter Balls     • Boundary Hit   • Net Run Rate Change
                                                   • Current Batting Order    • Dot Ball       • Player of Match
                                                   • In-Match Wickets Fallen
   
   ✅ PERMITTED IN X(t^-)   ✅ PERMITTED IN X(t^-)  ✅ PERMITTED IN X(t^-)      ❌ TARGET ONLY   ❌ STRICTLY PROHIBITED
```

## 3. Four Taxonomy Classes of Leakage Risks

Operation Pink Panther explicitly categorizes and audits four distinct classes of leakage risk:

### 3.1 Class 1: Direct Temporal Delivery Leakage
- **Definition:** The inclusion of variables in $\mathbf{X}(t^-)$ that encode or correlate with events occurring during or after delivery $t$.
- **Audit Findings:** 
  - Variables such as `runs_off_bat`, `extras`, `wides`, `noballs`, and `wicket_kind` are strictly quarantined as target outcome variables $Y(t)$.
  - Match-level final outcomes (`win_team_id`, `margin`, `result`) are strictly excluded from pre-delivery feature vectors.
- **Status:** **VERIFIED PASS (Zero Direct Temporal Leakage).**

---

### 3.2 Class 2: Aggregation & Baseline Leakage
- **Definition:** The inclusion of current match data in historical aggregations (e.g., calculating a venue's average run rate using matches that include the match being predicted).
- **Audit Findings:**
  - Venue baselines (`venue_baselines.csv`) and competition baselines (`competition_baselines.csv`) are calculated using empirical Bayes shrinkage across historical tournaments.
  - To achieve complete mathematical purity in cross-validation, out-of-fold venue baselines are enforced in Pillar 1 and Pillar 3 validation splits.
- **Status:** **VERIFIED CONTROLLED (Fold-Isolated Baselines Enforced).**

---

### 3.3 Class 3: Dynamic Opponent-Strength Leakage
- **Definition:** Calculating pre-match team ratings using match results that occur after the match in question.
- **Audit Findings:**
  - `team_pre_match_elo.csv` was audited line-by-line. Every Elo rating is computed strictly chronologically using match results prior to `match_date`.
  - The outcome of match $M$ updates the Elo rating for match $M + 1$, never for match $M$ itself.
- **Status:** **VERIFIED PASS (Strict Chronological Pre-Match Elo Updates).**

---

### 3.4 Class 4: Endogenous Form & Skill Self-Absorption
- **Definition:** Features generated by the active player in immediate prior deliveries leaking into the counterfactual population baseline.
- **Audit Findings:**
  - Incorporating `runs_last_12_balls` (Specification A) causes an elite player's recent boundaries to raise the baseline against which they are immediately evaluated.
  - While not a temporal violation (the past 12 balls did happen before $t^-$), it represents an **attribution distortion**.
- **Governance Remedy:** **Specification B (which explicitly ablates recent 12-ball features) was frozen as the primary estimand** in Section 3 of `stage_4_0_reliability_estimand.md`.
- **Status:** **RESOLVED BY ESTIMAND FREEZE (Specification B Adopted).**
